# Voltra Learnings - 2026-02-19

## Source Set
- Synthesized from 72 completed plans in `planning/complete/`.
- Focus areas most represented: indexing, tests/specs, exports/barrels, native routing, docs/TypeDoc, ORM/DAC, and CI build reliability.

## High-Signal Engineering Learnings

### 1) Treat indexing as a namespaced, consistency-sensitive system
- Index keys must be type-qualified to avoid multi-type field collisions.
- Update flows must support full replacement semantics (not append-only) so removed tokens/fields do not leave stale query hits.
- Deployment-specific table names must be explicit and injected; hidden defaults create environment drift and brittle CI/runtime behavior.

### 2) Keep authorization context explicit and per-request
- DAC access context should be passed per operation, not captured via implicit global/request-state coupling.
- Ownership/tenant scoping works best as explicit path-prefix policy composition.
- Missing access context should fail loudly; permissive fallbacks become security foot-guns.

### 3) Route maps should adapt signatures, not mutate domain contracts
- Wrapper layers should normalize invocation shape and protect service boundaries.
- When a wrapper causes argument shifting, fix routing/wrapper behavior instead of weakening core validators.
- Prefer a single ORM service instance pattern plus per-call context to reduce hidden state and churn.

### 4) Exports are a product surface, not just build plumbing
- Curated `exports` entrypoints reduce invalid deep import suggestions and long-term API drift.
- Barrel structure must be intentional: one canonical path per symbol where possible.
- Do not leak unstable generated artifacts into importable surfaces.

### 5) Test strategy should mirror real use while staying deterministic
- In-memory DB/index backends are the preferred foundation for DBX/E2E contract coverage in CI.
- JSON specs + nearby `*.test-utils.ts` are effective when scenarios remain modular and readable.
- High-value regressions to lock down: index collisions, stale index state after updates, route-wrapper arg mismatches, native navigation regressions.

### 6) Documentation quality is part of API correctness
- Doc comments must track exported types/functions as contracts evolve.
- TypeDoc entry points should mirror public package exports; docs break when entrypoints drift.
- Grouping and comment coverage improve discoverability and reduce onboarding time for consumers.

### 7) Cross-platform UI layers need strict shared contracts
- Web/native parity improves when shared core logic is renderer-agnostic and platform wrappers stay thin.
- Avoid React hook instability by preferring stable component patterns over ad hoc inline renderer functions.
- Native routing/back button/history behavior needs dedicated regression coverage; assumptions from web do not hold.

### 8) CI failures are usually architecture signal, not just patchwork chores
- Repeated CI failures often traced back to unclear ownership boundaries (docs vs exports vs generated files vs runtime config).
- Durable fixes came from consolidating contracts, deleting duplicate logic, and adding regression tests, not one-off suppressions.

## Recurring Anti-Patterns To Avoid
- Implicit defaults for deployment-specific infrastructure names.
- Public APIs that rely on hidden request-time mutable state.
- Cross-barrel duplicate exports that create ambiguous import paths.
- “Fixing” validation to absorb routing bugs.
- Leaving generated/type docs out of sync with actual `package.json` exports.

## Preferred Execution Pattern (Based on What Worked)
1. Start with a written phase checklist and explicit non-goals.
2. Land contract changes with compatibility notes.
3. Add/adjust targeted regressions in the same change set.
4. Verify with `yarn test` and, when relevant, `yarn doc` + site builds.
5. Update docs/exports together so consumer surface remains coherent.

## Practical Defaults For Future Work
- Default to in-memory contract testing first, then environment-specific wiring.
- Keep barrels minimal, deterministic, and documented.
- Model ownership and access as explicit policy composition inputs.
- Require explicit config where values are environment-specific.
- Assume every bug fix needs at least one regression spec near the affected area.
