## Distilled Learnings

### 1) Normalize Inputs Early and Keep Internal Semantics Centralized
- Routing, service URLs, and API request surfaces stay reliable when broad consumer inputs are normalized immediately into a single internal shape.
- `Route` path handling benefited from normalizing strings, arrays, and per-path exactness configs before matching.
- Request-path joining should reuse shared path semantics rather than preserve raw slash segments.
- Consumer-facing route context should expose readable slash-delimited paths while internal matcher state remains private and purpose-built.

### 2) Stable Framework Primitives Produce Better Consumer APIs
- Hooks and client APIs become safer when they align with the semantics of their underlying framework primitives instead of wrapping them in ad hoc contracts.
- Application state controllers should expose stable setter-compatible functions and support functional updates directly.
- Loader hooks are easier to consume when they return typed controller props alongside fetch lifecycle state rather than hiding the local state channel.
- Public APIs should place optional config in predictable positions and keep transport/client/server contracts aligned end-to-end.

### 3) Shared Cross-Platform Behavior Should Live in Voltra-Owned Core Logic
- Web, app, and native routing should share path/history behavior, with only runtime-specific mechanics isolated in platform wrappers.
- Relative navigation should resolve from the matched route scope where an adapter is acquired, not from the global app path.
- Native/mobile support is most reliable when path matching and parameter handling stay in Voltra-owned routing primitives instead of drifting into platform-specific state systems.
- First-class link/navigation components help lock shared behavior into the public API rather than relying on consumers to rebuild it.

### 4) Configuration Should Be Explicit, Typed, and Backwards-Compatible
- New feature surfaces work best when config is explicit, narrowly typed, and layered onto existing behavior instead of replacing it.
- ORM update operators, indexing tags, gateway authorizer ARNs, and auth resource ids all benefited from dedicated config objects and shared exported types.
- Manual override hooks are valuable, but they should sit on top of deterministic defaults such as derived indexing config or deployment hashes.
- Consumers should not need `any` casts or guessed internal resource ids to use advanced features.

### 5) Deterministic Invalidation and Reconciliation Are Core Infrastructure Patterns
- Infra and indexing systems need first-class reconciliation mechanisms rather than assuming writes only flow through ideal paths.
- API Gateway deployment replacement should be driven by a canonical hash of deployment-relevant config, with manual suffixes only as an escape hatch.
- Indexing support needs both declarative field tagging and explicit maintenance utilities for reindex/cleanup flows when schemas or out-of-band writes change.
- Deterministic fallback behavior is preferable to partial cleverness when correctness could drift.

### 6) Validation Must Reflect Real Data Semantics, Not Truthiness Shortcuts
- Required-value validation must treat `false` and `0` as present values; truthiness-based checks produce real regressions in seed data and forms.
- Preflight validation in scripts is worthwhile when operational workflows depend on external datasets.
- Parser and validator contracts must agree on literal-value semantics, especially for booleans, numbers, and constrained strings.
- When debugging validation failures, capture full result objects and per-field error maps rather than only top-level status.

### 7) Completion Standards in This Repo Include Tests, Docs, Exports, and Examples
- Feature work is not complete here until specs, doc comments, exports, and nearby examples are updated together.
- Focused regression tests are useful, but broader suite runs are still needed after shared-surface changes.
- Plans that kept explicit verification evidence, root-cause notes, and completion checklists were easier to trust and easier to synthesize later.

## Reusable Standards for Future Work
- Normalize flexible public inputs into one internal representation immediately.
- Put shared semantics in central utilities; keep platform wrappers thin.
- Prefer stable framework-native contracts over custom callback semantics.
- Add explicit typed config objects for advanced behavior instead of positional special cases.
- Use deterministic hashes or derived config for invalidation rather than manual churn.
- Treat validation, tests, docs, exports, and examples as part of the same deliverable.
