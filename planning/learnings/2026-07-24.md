## Indexing and Structured Search

Link & Lock established the production direction for Voltra indexing: use one collision-safe, versioned physical index
table for structured, full-text, exact, relationship, occupancy, missing-value, and generation record families. Every
physical key should flow through centralized structural key factories and codecs. Raw concatenation of user-controlled
type, field, value, token, relationship, or document identity segments is a correctness risk because delimiters, Unicode,
numeric IDs, and physical attribute names can collide unless encoded consistently.

Structured search correctness depends on deterministic source traversal and canonical verification. Candidate IDs from
term, range, generated, sort, or occupancy streams are not truth by themselves; complete predicates must be checked
against canonical structured `docFields`. This keeps stale derived rows, coarse occupancy cells, missing optional values,
and OR/AND composition from producing false matches or hiding live matches.

Global sorting must be treated as an ordered stream problem, not as page-local hydration sorting. For one scalar
structured-indexed sort field, traverse the field's native ordered range stream, verify the criteria as candidates pass,
and keep cursor state bounded. Missing optional sort values remain visible through a deterministic missing-value stream
after present values. Unsupported or multi-sort shapes should fall back to exhaustive comparison rather than silently
omitting documents.

The data-skipping layer solves sparse criteria plus unrelated global sort by mapping criterion chunks to exact sort
tokens in the existing ordered stream. Occupancy cells are boolean hints and contain no document IDs. They may create
false positives, especially after interrupted or concurrent writes, but must never create false negatives after completed
writes. Empty occupancy should be removed only with concurrency-safe proof; otherwise compaction/rebuild generations
reclaim stale cells safely.

Occupancy blocks are immutable value-space intervals, never mutable positions or page numbers. String chunks use a
case-preserving prefix of up to three Unicode code points with distinct exact short-value buckets. Ordinary numeric
fields use decade chunks, while fields tagged `tags.indexed.decimal` use unit chunks. Sort blocks are the exact existing
sortable tokens; adding a second sort-token quantization layer would weaken ordering and increase complexity.

Occupancy cursors are generation-pinned and small. They store the active generation, present/missing phase, exact
sort-token boundary, and backend continuation for the current token. The original query supplies direction. Cursor reuse
with changed criteria, sort direction, tokenizer, mapping, or generation is invalid; a cursor from a non-active occupancy
generation returns zero results with no successor cursor.

Normal CRUD should maintain the active occupancy generation from the first write. Rebuild/backfill is operational repair,
compaction, or index-rule migration tooling, not a required initial setup step. During rebuilds, writers dual-write active
and building generations, activation is an explicit compare-and-swap, and old-generation reclamation can proceed after
queries stop targeting it.

## Mutation and Consistency

Voltra's indexing mutation model is optimistic and forward-only. Canonical `docFields` compare-and-swap remains separate
from derived structured, full-text, relationship, and occupancy writes. Derived mutations can be coordinated and batched
in DynamoDB groups of at most 25 operations with unprocessed-item retry, but those batches must not be described or
treated as transactions. Failed or interrupted writes converge through retry, repair, canonical verification, and
generation rebuild rather than rollback.

DynamoDB's eventual-consistency behavior must be represented in tests. Confirmation reads can be stale, property order
can vary, and real contention must remain distinguishable from semantic equality. Production drivers should remain
decoupled, but test-only Dynamo-shaped clients should be capable of reproducing stale read-after-write visibility so
structured writers are validated against realistic behavior.

Index maintenance should not reject omitted optional indexed fields. Validation is responsible for required field
failures; indexing should normalize missing full-text values to empty content or skip undefined structured values as
appropriate. The old `INDEXING_MISSING_INDEX_FIELD` path was redundant and contradicted backend normalization behavior.

Numeric ordering is a TypeInfo contract. Number fields need order-preserving numeric encoding, with non-finite values
rejected and `-0` normalized. String-like fields keep string comparison. Mixed string/number unions do not receive a
range-ordering guarantee.

## DynamoDB ORM Driver Contracts

DynamoDB ORM sort-field behavior must be explicit. The driver can treat the first `sortFields[0].field` as a GSI
`IndexName` and honor `reverse`, but this is an opt-in DynamoDB-specific behavior. Without the config flag, sort fields
fall back to in-memory sorting so ordinary callers do not accidentally depend on physical index names. Additional sort
fields are ignored by the DynamoDB driver.

Driver-specific config types are part of the public API surface. Types such as DynamoDB-specific ORM config should be
exported through the API ORM driver barrel and verified with consumer import coverage from `@resistdesign/voltra/api`.

DynamoDB expression generation must use canonical operand shapes. `IN` and `NOT_IN` use `valueOptions`, range operators
use two-item tuples, valueless operators have no operands, and standard operators should be modeled with
operator-discriminated criterion types. Candidate expansion must generate one stable, collision-safe placeholder per
candidate and reject empty or missing candidate sets before command dispatch.

DynamoDB update expressions must serialize non-scalar values correctly. Lists and objects used in update expression
attribute values should be marshalled through the same value-shape-aware path as other item data, not assumed to be
scalar strings or numbers.

## App Service Behavior

`sendServiceRequest` is now JSON-only. Parsed JSON values are returned directly, and unparseable response bodies resolve
to `undefined` rather than being wrapped as fallback strings. Tests and callers should assume service responses are
structured JSON payloads.

Application state loading supports canceling pending requests when a new request starts. The configuration flows from
`ApplicationStateLoaderConfig` through `useApplicationStateLoader` to the shared app service helper. Future request
features should preserve that through-line rather than adding component-local cancellation logic.

## Cursor and Pagination Obligations

Terminal cursors must be truthful. Leaf term/range searches should emit a cursor only when the backend supplies
continuation state, and the `SearchStructured` handler must not resurrect an exhausted incoming cursor. Empty
intermediate work is not the same as exhaustion; exhaustion requires no ready IDs and no remaining source.

Compound structured cursors should remain positional and bounded. Regenerate deterministic candidate sources, consume
bounded backend pages atomically, store only per-source continuation plus bounded ready overflow, and let canonical
verification decide matches. This avoids cursor state that grows with result history and prevents replaying page one
after terminal pages.

ORM visible pages must fill through hydration misses and DAC rejection until the search is exhausted or the caller page
is full. Broad fallbacks should happen only for explicit unsupported-plan errors; operational cursor/backend failures
should propagate instead of being silently swallowed.

## Validation Expectations

Indexing and ORM work requires focused regressions plus broader validation because small-looking changes often affect
driver shape, public exports, docs, demos, and consumer import behavior. Reusable validation patterns from these plans
include focused JSON specs, core/native suites, DBX medium coverage, package/declaration/export checks, consumer install
and import smoke tests, TypeDoc generation, demo API/type generation, IaC generation, Astro production build, and final
diff review.

For major indexing changes, tests should cover delimiter and Unicode collisions, numeric edge cases, stale derived rows,
missing optional values, reverse ordering, terminal cursors, multi-page continuation, active-generation rebuilds,
old-generation cursor termination, batch caps, unprocessed-item retry, DynamoDB-shaped request output, and in-memory
parity without production dependency crossover.
